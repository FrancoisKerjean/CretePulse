Comment on le construit

Zéro réécriture. Le codebase Next.js actuel EST l'app : on ajoute une couche d'installation et on réorganise les surfaces existantes.

1

Un seul codebase

Le site crete.direct (Next.js, Vercel) reste l'unique source. Chaque deploy met à jour le site ET l'app instantanément. Rien à re-soumettre aux stores.

existant
2

Couche PWA

Manifest + service worker : le site devient installable, les horaires bus restent consultables hors-ligne, le prompt « Installer » apparaît au bon moment.

~3-4 jours
3

Shell « Maintenant »

/explore passe en écran d'accueil app : géoloc, panneau « près de toi » (plage notée, prochain bus GPS), tab bar Carte / Bus / Plages / Devis.

~1 semaine
4

Stores

Play Store en TWA (coquille officielle autour de la PWA, 25$ une fois, ~1 jour). App Store ensuite via Capacitor, seulement si les installs Android le justifient.

conditionnel

Le plan en lots

Le lot 0 tourne pendant qu'on développe : c'est lui qui valide (ou tue) les lots 3+.

Garde-fou acté le 10/07 : les lots 0-1-2 servent le site actuel même si l'app ne décolle pas (mesure, offline, meilleure UX mobile pour 3 000 mobinautes/mois sur /explore). La décision stores (lots 3-5) se prend sur les chiffres du lot 0 après 3 semaines de pleine saison : retour J+1 ≥ 8% des mobiles features outils, ou clic bannière ≥ 3%.
